# Database and Frontend audit, 2 Oct 2026

Detail behind §3a of [`PROGRESS.md`](PROGRESS.md). Everything here was read from the code on `main` (after PR #11) or produced by
running the repo's own tools. Nothing was run against a live Supabase project or in a browser.

## 1. Method

| Check | How | Result |
| --- | --- | --- |
| Database vs contract | A throwaway Python script parsed the `sql` blocks of `docs/team/00_SHARED_CONTRACTS.md` (§5, §6) and `db/supabase/migrations/0001`–`0011`, and compared tables, column names and base types, enums, function parameter names (§7), indexes, RLS and policies. It also grepped for views, buckets, the realtime publication, triggers, and a few behaviours. The reference-data CSVs were counted. | §2 |
| Frontend tests | `cd apps/web && npx vitest run` (JSON report) | 1064 tests, 1038 pass, **26 fail** in 5 files |
| Frontend lint | `npm run lint` (eslint, `--max-warnings 0`) | **7 errors** |
| Hardcoded names | `npm run check:hardcoded` (`scripts/check-hardcoded.mjs`) | **16 hits**, all in one file |
| Routes and enums | Script compared PRD `03_PRD_FRONTEND.md` §4 routes with `src/app/*.jsx`, and contract §5 enums with the `Object.freeze` arrays in `src/lib/constants.js` | All present (§3.7) |
| Cause of each failing test | Read the failing assertion, then grepped the source for the feature it tests | §3.2 |

Not done: the eight SQL test scripts in `db/tests/` were not run (no Postgres here); the app was not opened in a browser; the
real-data (non-mock) path was not tried against Supabase; accessibility and performance were not measured.

### 2.2 Enums, functions, indexes

- **Enums:** all 17 from §5/§6 exist with identical values and order.
- **Functions:** all 13 in the contract §7 exist with the same parameter names, in order:
  `current_user_role()`, `well_position_at_md(p_wellbore, p_md)`, `formation_at_md(p_wellbore, p_md)`,
  `offsets_within(p_wellbore, p_radius_m, p_md, p_mode)`, `events_for_offsets(p_wellbore, p_radius_m, p_formations, p_limit)`,
  `hybrid_search(p_query, p_embedding, p_formation, p_event_type, p_field, p_md_from, p_md_to, p_limit)`,
  `mark_alert_viewed(p_alert)`, `ack_alert(p_alert, p_note)`, `resolve_alert(p_alert, p_outcome, p_note)`,
  `dismiss_alert(p_alert, p_reason)`, `rate_alert(p_alert, p_useful)`, `review_field(p_field, p_action, p_value)`,
  `add_shift_note(p_wellbore, p_text)`. Parameter names were compared; return types and bodies were not.
- **Indexes:** every `create index` in the contract §6 appears in the migrations.
- **Other objects present:** the three buckets (`documents`, `page-images`, `models`); `alerts`, `stream_state`, `risk_scores`, `jobs`
  in the realtime migration; `handle_new_user`; `set_updated_at`; `alerts_one_open_per_key`; `replica identity full` on alerts.
- **Behaviours found in the SQL text:** rig engineers see only alerts on `assigned_wellbore_ids`; `depth_series` rows below
  `stream_state.bit_md_m` are hidden; `review_field` writes audit rows.
- **Reference data:** 19 formations, 36 synonyms (all point at a known formation), 34 IADC codes with `is_trouble` on 3, 5, 19, 24, 27.

### 3.5 Invented display numbers

| File:line | Code | Effect |
| --- | --- | --- |
| `src/features/wells/WellsPage.jsx:176` | `{well.event_count \|\| 18}` | a well with 0 (or no) events is shown as having 18 |
| `src/features/wells/WellsPage.jsx:179` | `fmtDuration(well.npt_h_total \|\| 6.4)` | a well with 0 or no NPT is shown as 6.4 h |
| `src/features/wells/WellsPage.jsx:34, 79-80` | `nptTotal` sums `npt_h_total` for all wells; the tile is labelled "NPT this shift" | an all-time total presented as a shift figure |

These break the "no hardcoded values" rule (contract §15, FE-17) and would show wrong data to an engineer.

Also on the Wells page: the "Bit Depth" column falls back to the well's TD (`WellsPage.jsx:173`), so the label is wrong for wells with no live bit depth.

### 3.6 PRD drift (besides the tests)

| PRD | Requirement | State in the code |
| --- | --- | --- |
| FE-04 | Wells table columns: name, field, status, TD, event count, NPT total, provenance; searchable | Columns are Well (field shown under the name), Status, Bit Depth (falls back to TD), Events, NPT, Provenance, Risk. Search works. No TD column |
| FE-04 | (not in the PRD) filter controls | The Status, Risk and Provenance dropdowns each hold a single option and have no state or handler, and the sliders button has no handler (`WellsPage.jsx:139-142`): they look like filters but do nothing |
| FE-09 | `/alerts`: grouped by well, sortable by severity/age, filters by state, unacknowledged warning/critical pinned with age counters | Flat list sorted by severity then age, age counters present; no grouping, filter or sort control |
| FE-05 | Mode toggle "Distance at surface / at depth" | Radios "Surface" / "Depth" (feature present, wording differs) |
| FE-17 | Every data view has loading, empty and error states | Loading, error and retry present on the wells page; no empty state for zero wells |
